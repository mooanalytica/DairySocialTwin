# Key-point Trajectory Extractor (Stage 1)

This repository contains the cluster-ready pipeline for cow detection, tracking,
pose estimation, identity assignment, key-point trajectory export, and the
current downstream interaction CSV outputs produced by the same run.

The intended entry point is:

```bash
python -u run_full_interaction_pipeline.py
```

For Narval/A100 jobs, use the Slurm batch file in `cluster/narval` as the
reference launcher:

```bash
sbatch cluster/narval/run_gx040008_a100.sbatch
```

## Runtime Environment

Use the SIF image shared in the project progress check-up. This repository is
not distributed with a requirements file, and dependency installation is not
part of the submission workflow.

The Narval launcher expects the SIF path to be configured in:

```bash
IMAGE_HOST="/home/your_account/scratch/dcsna_a100_raw_4090.sif"
```

Edit this variable if the SIF is stored elsewhere. The batch script copies the
image into `SLURM_TMPDIR` before running the preflight and pipeline.

## Required Model Files

Stage 1 model weights are intentionally not included in this repository. Obtain
them from Sibi's project and place them under `models/` with these exact names:

```text
models/Object_Detection_Trained_Model.pt
models/Identification_Model_Trained.pt
models/Keypoint_Model_Trained.pth
```

The current Stage 2 inference checkpoints are small enough to keep in the
repository and are expected at:

```text
models_new/stage2_interaction_gate_best.pt
models_new/stage2_valence_inception_best.pt
```

## Cluster Path Setup

The Narval batch script uses these host-side variables:

```bash
PROJECT_HOST="/home/your_account/scratch/DCSNA"
SCRATCH_HOST="/home/your_account/scratch"
IMAGE_HOST="/home/your_account/scratch/dcsna_a100_raw_4090.sif"
SOURCE_VIDEO_HOST="/home/your_account/scratch/V0531/Dairy Farm Videos/May 7 2025 Dairy Farm 3 Videos/Video/Gopro2/GX040008.MP4"
```

Set `your_account` and `SOURCE_VIDEO_HOST` for the target run. The public Slurm
account in the batch file is intentionally left as `rrg-sureshra`.

The Python entry point contains local fallback defaults for development. On the
cluster, use the Slurm launcher or pass explicit `--input-dir`, `--output-dir`,
and checkpoint paths instead of relying on those defaults.

## Outputs

A run writes a per-video output directory containing files such as:

```text
tracking_boxes.csv
keypoints.csv
manifest.json
interactions.csv
no_interactions.csv
adjacency_*.csv
proximity_percentiles.csv
annotated MP4 outputs
```

These files, along with Slurm logs and runtime caches, are generated artifacts.
They are not kept in this repository and should be regenerated by rerunning the
pipeline.

## Vendored Code

Vendored ByteTrack and ZebraPose/ViTPose code is stored as `vendor.zip` to keep
the repository file tree compact. Extract it before running the preflight or the
pipeline so that the project root contains:

```text
vendor/ByteTrack
vendor/ZebraPoseViTPose
```

The pipeline imports these paths directly, and the Narval preflight checks that
the extracted `vendor/` tree is present.
